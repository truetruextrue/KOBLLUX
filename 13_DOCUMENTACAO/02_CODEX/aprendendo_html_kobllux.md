### Capítulo 1 – Introdução a frames, iframes e carregamento dinâmico de HTML

#### 1.1 Contextualização e importância do tema

Nas aplicações web modernas, a exibição dinâmica de conteúdos variados dentro de uma mesma página se tornou um pilar fundamental. Seja para menus que acompanham o usuário em todas as páginas, sistemas de chat integrados, players multimídia ou dashboards interativos, a necessidade de carregar e controlar diferentes documentos HTML completos, mantendo independência de estilo, comportamento e controle, é real e indispensável.

O uso de frames já foi uma prática muito comum há duas décadas, mas caiu em desuso devido a problemas de usabilidade, SEO e compatibilidade. Hoje, o recurso padrão para essa função é o `iframe`, que funciona como uma janela para outro documento HTML independente, dentro da sua página principal.

#### 1.2 O que são frames e iframes?

```
frame  → tecnologia antiga (<frameset> + <frame>). Dividia a tela em áreas fixas,
          cada uma carregando um documento diferente. Atualmente obsoleto.
          Problemas: ruim para SEO, navegação, impressão e responsividade.

iframe → Inline Frame (<iframe>). Recurso atual padrão.
          Permite embutir um documento HTML dentro do documento principal.
          Tem seu próprio contexto, CSS e JS, isolado do documento pai.
```

Exemplo básico de iframe:

```html
<iframe src="pagina.html" width="400" height="300" style="border:none;"></iframe>
```

#### 1.3 Por que usar iframe?

```
Isolamento:     evita conflitos de CSS e JS entre o conteúdo embutido e o principal.
Modularidade:   pode carregar conteúdos completos, páginas com cabeçalho, corpo,
                estilos e scripts próprios.
Flexibilidade:  permite criar menus, popups, players, chats que não interferem
                diretamente no DOM principal.
```

#### 1.4 Carregamento dinâmico de HTML completos

Ao carregar um HTML completo num iframe, você pode ter:
- Cabeçalhos (`<head>`) com estilos e scripts próprios
- Corpo (`<body>`) com o conteúdo visual e funcional
- Scripts rodando dentro do iframe, sem afetar o documento pai

Isso é perfeito para o caso de menus flutuantes, botões, e conteúdos complexos isolados.

#### 1.5 Principais desafios ao trabalhar com iframes

```
1. Sobreposição e visibilidade
   Por padrão, o iframe cobre a área onde está posicionado, e o fundo branco do
   HTML carregado dentro dele pode esconder elementos do documento principal.
   → Se quiser só um botão flutuante visível, precisa que o fundo do iframe seja
     transparente, ou que o botão esteja no documento pai.

2. Comunicação entre iframe e página principal
   O conteúdo do iframe e a página pai não compartilham diretamente variáveis JS,
   por questões de segurança (mesmo domínio, permissões).
   → Para trocar dados, é preciso usar o postMessage.

3. Estado e controle de mídia
   Se dentro do iframe existe áudio ou vídeo, para evitar perder a música ao fechar
   ou ocultar o iframe, é necessário detectar se está tocando algo e decidir se
   pausa ou não o conteúdo.

4. Upload e carregamento de HTML locais
   Para ter menus rápidos ativados via upload local, você precisa ler o arquivo HTML
   e gerar uma URL interna (URL.createObjectURL) ou usar srcdoc para injetar o
   conteúdo no iframe.

5. Navegação interna e abas
   Se o iframe tem um menu com abas, precisa gerenciar isso dentro do iframe, ou
   controlar múltiplos iframes na página principal.
```

#### 1.6 Exemplo básico: iframe flutuante com botão interno

HTML do index principal:

```html
<body>
  <iframe
    id="flutuante"
    src="botao.html"
    style="position: fixed; bottom: 20px; right: 20px;
           width: 100px; height: 50px; border:none; background: transparent;"
    allowtransparency="true"
  ></iframe>
</body>
```

Conteúdo do botao.html:

```html
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <style>
    body {
      margin: 0;
      background: transparent;
      overflow: hidden;
    }
    button {
      width: 100%;
      height: 100%;
      font-size: 16px;
      cursor: pointer;
    }
  </style>
</head>
<body>
  <button>Meu Botão Flutuante</button>
</body>
</html>
```

**Nota:** Para que o fundo do iframe seja transparente, o atributo `allowtransparency="true"` e o CSS `background: transparent` no corpo do iframe são importantes. Alguns navegadores limitam transparência em iframe, principalmente se carregar arquivos externos.

### Capítulo 2 – Estilização e posicionamento avançado de iframes e botões flutuantes

#### 2.1 Introdução

Vamos aprofundar no controle visual e funcional do iframe para que ele:
- Fique fixo e visível no local desejado, sem interferir na navegação da página principal
- Permita que elementos fora do iframe possam ser clicados, se necessário
- Apresente transparência para não sobrepor toda a página
- Seja flexível para abrir, fechar, ocultar e mostrar
- Use camadas (z-index) corretamente

#### 2.2 CSS essencial para iframes flutuantes

**a) position: fixed ou absolute**

```css
#iframeFlutuante {
  position: fixed;    /* fixed = em relação à viewport, fica no lugar ao rolar */
  bottom: 20px;
  right: 20px;
  width: 120px;
  height: 50px;
  border: none;
  z-index: 9999;      /* garante que fique na frente */
  background: transparent;
}
```

**b) z-index** — controla a ordem das camadas na tela. Um valor maior coloca o elemento na frente de outros com valores menores. Para funcionar, o elemento deve ter `position` diferente de `static`.

**c) Transparência do fundo do iframe**

Para que o iframe tenha fundo transparente:
- A página carregada dentro do iframe deve ter `background: transparent` no CSS do `body`
- O iframe no pai pode receber `allowtransparency="true"`
- Use `background: transparent` no `<iframe>` e no documento carregado

**d) pointer-events**

```css
#iframeFlutuante {
  pointer-events: none;  /* o iframe não responde a cliques */
}
```

**Atenção:** `pointer-events: none` impede que qualquer coisa dentro do iframe seja clicável também. Use com cuidado quando há botões dentro.

#### 2.3 Como deixar só o botão flutuante visível

Estratégias para não cobrir a página inteira:

```
1. Criar o HTML do iframe com fundo transparente:
   body { margin: 0; background: transparent; overflow: hidden; }

2. Ajustar o tamanho do iframe para o mínimo necessário (só o botão).

3. Usar CSS para que o botão ocupe o espaço inteiro do iframe.

4. Alternativa simples: criar o botão diretamente na página principal, fora
   do iframe, usando position: fixed — para ter controle absoluto.
```

### Capítulo 3 – Comunicação entre frames e página principal: postMessage e eventos

#### 3.1 Introdução

Quando você trabalha com iframes carregando documentos HTML completos, cada iframe é um contexto separado. O código JavaScript rodando dentro do iframe e o código da página principal não compartilham diretamente variáveis, funções ou estados, por razões de segurança e isolamento.

Para coordenar ações — pausar áudio, fechar o iframe, ocultar menus, sincronizar estado — é fundamental usar a API `postMessage`, um canal seguro para enviar mensagens entre janela pai e iframe, e vice-versa.

#### 3.2 Como funciona o postMessage

```javascript
// Na janela que envia a mensagem:
targetWindow.postMessage(message, targetOrigin);

// targetWindow  → objeto Window que receberá a mensagem
//                 (ex: iframe.contentWindow ou window.parent)
// message       → qualquer dado serializável (string, objeto JSON)
// targetOrigin  → 'https://meusite.com' (seguro) ou '*' (qualquer origem)
```

#### 3.3 Página pai enviando mensagem para iframe

```javascript
const iframe = document.getElementById('meuIframe');

// Envia mensagem para o iframe
iframe.contentWindow.postMessage({ comando: 'fecharMenu' }, '*');
```

#### 3.4 Iframe escutando mensagens do pai

```javascript
// No HTML carregado dentro do iframe:
window.addEventListener('message', (event) => {
  // Pode-se checar event.origin para validar a origem
  const data = event.data;

  if (data.comando === 'fecharMenu') {
    document.body.style.display = 'none'; // oculta o menu no iframe
  }
});
```

#### 3.5 Iframe enviando mensagem para a página pai

```javascript
// Dentro do iframe:
window.parent.postMessage({ evento: 'menuFechado' }, '*');

// Na página pai:
window.addEventListener('message', (event) => {
  if (event.data.evento === 'menuFechado') {
    console.log('O menu foi fechado dentro do iframe');
  }
});
```

#### 3.6 Boas práticas para postMessage

```javascript
// 1. Valide o event.origin para segurança:
window.addEventListener('message', (event) => {
  if (event.origin !== 'https://meusite.com') return;
  // processa mensagem
});

// 2. Use estruturas claras:
{ comando: 'pausarAudio' }  // ✓ claro e específico
'pausar'                    // ✗ ambíguo

// 3. Trate mensagens inesperadas graciosamente (if/switch, não lança erro)
```

#### 3.7 Aplicações práticas para o projeto

**a) Pausar ou continuar áudio dentro do iframe:**

```javascript
// Na página principal:
function pausarAudioNoIframe() {
  iframe.contentWindow.postMessage({ comando: 'pausarAudio' }, '*');
}

// No iframe:
window.addEventListener('message', (event) => {
  if (event.data.comando === 'pausarAudio') {
    const audio = document.querySelector('audio');
    if (audio && !audio.paused) audio.pause();
  }
});
```

**b) Botão fechar no iframe notifica o pai:**

```javascript
// No iframe:
document.getElementById('btnFechar').addEventListener('click', () => {
  window.parent.postMessage({ evento: 'fecharMenu' }, '*');
});

// Na página pai:
window.addEventListener('message', (event) => {
  if (event.data.evento === 'fecharMenu') {
    document.getElementById('meuIframe').style.display = 'none';
  }
});
```

**c) Sincronizar aba ativa com localStorage:**

```javascript
// No iframe — quando muda de aba:
function mudarAba(idAba) {
  window.parent.postMessage({ evento: 'abaMudou', aba: idAba }, '*');
}

// Na página pai:
window.addEventListener('message', (event) => {
  if (event.data.evento === 'abaMudou') {
    localStorage.setItem('abaAtiva', event.data.aba);
  }
});
```

**index.html:**

```html

```

```html

<audio id="audio" src="musica.mp3" controls autoplay></audio>

<script>
  document.getElementById('btnFechar').addEventListener('click', () => {
    const audio = document.getElementById('audio');
    if (!audio.paused) audio.pause(); // pausa se estiver tocando

```

**Lógica do congelamento (estilo iPhone):**

```javascript
// No iframe — verificar se há áudio/vídeo tocando antes de ocultar:
function ocultarComLogica() {
  const audio = document.querySelector('audio');
  const video = document.querySelector('video');
  const hasMidia = (audio && !audio.paused) || (video && !video.paused);

  if (hasMidia) {
    // Mantém tocando — apenas oculta visualmente
    window.parent.postMessage({ evento: 'ocultarSemPausar' }, '*');
  } else {
    // Nada tocando — pode fechar/pausar normalmente
    window.parent.postMessage({ evento: 'fecharMenu' }, '*');
  }
}
```

### Capítulo 4 – Gerenciamento de estado e armazenamento local para menus e uploads

#### 4.1 Introdução

Uma das grandes vantagens de sistemas dinâmicos baseados em frames e menus é a capacidade de lembrar preferências, conteúdos carregados e estados do usuário mesmo após recarregar a página ou em sessões futuras.

Para isso, o navegador oferece ferramentas poderosas: `localStorage` e `sessionStorage`. Este capítulo mostra como você pode usar esses recursos para guardar:
- Menus ativados e personalizados
- Uploads locais de arquivos HTML para carregamento rápido
- Estados de abas abertas
- Informações básicas da conta (token, login)
- Outras preferências relevantes para o sistema

#### 4.2 Diferenças entre localStorage e sessionStorage

```
Recurso          localStorage                     sessionStorage
─────────────────────────────────────────────────────────────────────────
Escopo           Armazena dados indefinidamente    Só durante a sessão atual
                 até serem apagados explicitamente  (fecha junto com a aba)
Compartilhamento Compartilhado entre abas          Isolado por aba/janela
                 do mesmo domínio
Limite           ~5MB (varia entre navegadores)    Mesmo limite
Uso típico       Preferências e dados persistentes Dados temporários da sessão
─────────────────────────────────────────────────────────────────────────
```

```javascript
// No input de upload:
document.getElementById('inputUpload').addEventListener('change', async (e) => {
  const file = e.target.files[0];
  if (!file) return;

  const reader = new FileReader();
  reader.onload = (evt) => {
    const htmlContent = evt.target.result;
    const chave = 'html_' + file.name;

    // Guarda o HTML no localStorage
    localStorage.setItem(chave, htmlContent);

    // Registra no índice de HTMLs salvos
    const indice = JSON.parse(localStorage.getItem('htmlsSalvos') || '[]');
    if (!indice.includes(file.name)) {
      indice.push(file.name);
      localStorage.setItem('htmlsSalvos', JSON.stringify(indice));
    }

    console.log(`HTML "${file.name}" salvo para ativação rápida.`);
  };
  reader.readAsText(file);
});
```
